# Improvement review (10 Nov 2026): two viewpoints

Two independent read-only reviews of the app: one from an FM long-save player's point of view, one from an engineer's.

## A. FM player / scout view
| # | Improvement | Why | Effort | Needs new data |
|---|---|---|---|---|
| A1 | The ★ searches hardcode years (`joined>=2037`, `contract<=2037`). Make them relative to the game date (e.g. `contract<=+12m`). | They go stale next season. | S | no |
| A2 | Confirm the unknown squad-status codes (9, 14, 16, 21, 22; "Fringe?", "Backup?"…). | "Not Needed" and loan statuses are what players hunt for. | S | screenshots |
| A3 | Add a **Loan targets** search: ≤21, youth or backup status at much bigger clubs, CA ≥ our squad median. | This is the main route for a League One club. | S | no |
| A4 | Split Join % into **Interest** and **Affordable**. | Today keen-but-pricey players look ungettable. | M | no (budgets would help) |
| A5 | The potential estimate assumes he reaches his full PA. Add a "realistic" mode (60–70% of the gap) or rename it "@PA". | Most players fall short of PA. | S | no |
| A6 | Split side roles by side (IF-L / IF-R…) and weight the stronger foot. | Inverted versus traditional winger is hidden today. | M | no |
| A7 | Show role scores as a percentile against your XI, your league and the league above ("fits our level"). | A score of 62 means little on its own. | M | no |
| A8 | **Track development across loads**: CA Δ and attribute Δ by UID since the last load or the season start. | This is the core long-save need. | M | no |
| A9 | **Risk flags** column: injury prone, inconsistent, big-match bottler, temperament, controversy. | The hidden attributes are the tool's edge. | S | no |

Not-decoded data, by value: transfer/loan-listed status and release clauses > club budgets > staff attributes > traits > season stats > disliked clubs.

## B. Engineering view
| # | Issue | Fix | Effort |
|---|---|---|---|
| B1 | Patch Doctor: after a *positive* shift the block length is too short. Every player throws, is skipped silently, and the list comes out empty. | Work out the length from the largest offset. Fail loudly if most reads fail. | S |
| B2 | Patch Doctor keeps the old `alternatives` paths. A garbage path could then win. | Save the found paths. Check that the first entries are real objects. | S |
| B3 | A retired anchor (e.g. Haaland retired in a late save) gives the wrong player class. | Take a majority vote across all anchors. | S |
| B4 | Anchor PA values may change after an FM database update. | Allow ±5, or check across the whole list instead. | M |
| B5 | Patch Doctor doesn't re-check person, contract, team, club, nation, career-stats offsets, or the extra class shift. | Run a sanity check per field and log any that fail. | M |
| B6 | Load makes about 35 tiny reads per player (~6M syscalls). | Read each struct in one go, cache names by pointer, optionally use threads. Load would drop from ~10 s to ~2–3 s. | M |
| B7 | No detection when FM changes the list mid-read or closes. | Re-check the list after loading. Abort on a high failure rate. | S |
| B8 | Handle leaks on an unknown build. The "FM still starting" Win32 error isn't handled. | Dispose properly and show a friendly message. | S |
| B9 | A recursive load after Patch Doctor can run twice. Shared data is set from worker threads. | Use a guard flag, and set the shared data on the UI thread. | S |
| B10 | No global exception handler. An `async void` load can crash the app. | Add handlers that show the ErrorDialog. | S |
| B11 | A corrupt override layout is ignored silently. The "newest template" depends on dictionary order. | Report the error. Sort templates by build. | S |
| B12 | Patch Doctor saves the layout in place, with no backup. | Write to a temp file, then replace it, keeping a `.bak`. | S |
| B13 | Negative PA (a range) isn't handled. Relation targets aren't checked for null. The game-date re-search is weak. | Use the midpoint of the PA range; add checks. | S |
| B14 | No tests. | Add an `IMemory` abstraction, snapshot-based golden tests, parser and date tests, and Patch Doctor tests with synthetic shifts. | M–L |

The app is confirmed strictly read-only: only `PROCESS_VM_READ | PROCESS_QUERY_INFORMATION`, with no write or protect calls.
